# Command-line interface (CLI) for headless batch mode
Command-line arguments offer a variety of options that generally override the corresponding parameters in the preferences.
The CLI option for mzmine offers to run one batch file (-batch). This batch file can be easily generated by another script 
or can be a standardized batch file for an analytical method that is applied to multiple datasets.

The most convenient way to apply a batch file to other datasets is to specify the **-input** and **-output** 
arguments to process all import files and to redirect all outputs to another directory. See examples below 
for how to process all .mzML files in a folder and to redirect outputs to a new directory and base filename. 

## Selecting a user

Running mzmine in CLI mode requires a [user](services/users.md) with a valid license. There are
three ways to provide one:

- **-cli-token "\<TOKEN\>"** (recommended for pipelines and servers): a token created in the
  [mzio user account console](https://auth.mzio.io/realms/mzio/account/) under **CLI tokens**. Every
  run automatically claims a free license from your license pool, so parallel runs need one free
  license each. See [CLI tokens for pipelines](services/users.md#cli-tokens).
- **-login** (web browser support required): signs in interactively and stores the user on this
  computer. The most recently active user is then automatically selected for mzmine processing.
  Without **-batch**, mzmine closes again after the login.
- **-user "path/to/user.mzuser4"**: uses a specific user file. Alternatively, provide only the user
  name, e.g. **-user testuser**, to use `testuser.mzuser4` from your system USER directory under
  /.mzmine/users/. This is mainly intended for
  [offline (airplane mode) licenses](services/users.md#offline-use), which are bound to one computer
  and do not require an internet connection.

Use **-list-users** to print all users available on this computer together with their license state.

!!! note
    Legacy `.mzuser` files from older mzmine versions use a different format and are rejected. Log
    in again via the graphical user interface, **-login**, or **-cli-token** to create a new user
    file.


## Windows

For command-line mode, the mzmine_console.exe is preferred as it will print the logging output to the console. 

An easy way to start mzmine with arguments is to create a shortcut to the mzmine.exe or the mzmine_console.exe, right-click, and define the target with additional arguments. This example runs mzmine in batch mode (headless), imports the specified batch file, overrides the memory management to **none** (which is the default), effectively using memory mapping to store and access spectral, centroid, and feature data from temporary files stored in the defined temp directory. By leaving out the _memory_ or _temp_ arguments, the values stored in the current _preferences_ file will be used, or the default values if no _preferences_ file was found.  

**Login to a user in command-line mode**
```
# login in browser
"C:\Program Files\mzmine\mzmine_console.exe" -login

# list all users available on this computer
"C:\Program Files\mzmine\mzmine_console.exe" -list-users
```

**Run headless with a CLI token (no interactive login)**
```
"C:\Program Files\mzmine\mzmine_console.exe" -cli-token "TOKEN" -batch "D:\batch\my_batch_file.mzbatch" -input "D:\Data\*.mzML" -output "D:\Results\basename"
```


**Process all .mzML files in a folder by the provided batch file, redirect output files to results folder and use a base filename, various export modules add a specific suffix**
```
"C:\Program Files\mzmine\mzmine_console.exe" -user "D:\user\testuser.mzuser4" -batch "D:\batch\my_batch_file.mzbatch" -input "D:\Data\*.mzML" -output "D:\Results\basename"
```

**Defining the temp folder, otherwise uses the one specified in local configuration**
```
"C:\Program Files\mzmine\mzmine_console.exe" -user "D:\user\testuser.mzuser4" -batch "D:\batch\my_batch_file.mzbatch" -temp "D:\tmpmzmine"
```

**Start mzmine batch with memory mapping (DEFAULT)**
```
"C:\Program Files\mzmine\mzmine_console.exe" -user "D:\user\testuser.mzuser4" -batch "D:\batch\my_batch_file.mzbatch" -memory none -temp "D:\tmpmzmine"
```


**Start mzmine batch on machines with enough memory (RAM) with -memory all** this will disable memory mapping to temporary files. 
```
"C:\Program Files\mzmine\mzmine_console.exe" -user "D:\user\testuser.mzuser4" -batch "D:\batch\my_batch_file.mzbatch" -memory all -temp "D:\tmpmzmine"
```

## macOS
If the app was installed to the _Applications_ folder, run this command in the terminal to run a batch file:
```
/Applications/mzmine.app/Contents/MacOS/mzmine -user "path/to/testuser.mzuser4" -batch /path/to/batch_file.mzbatch
```

```
/Applications/mzmine.app/Contents/MacOS/mzmine -user "path/to/testuser.mzuser4" -batch /path/to/batch_file.mzbatch -input "/path/to/data/*.mzML"
```

## Linux
If mzmine was installed (see instructions) correctly, run the code below to start mzmine in GUI mode or CLI batch mode:
```bash
/opt/mzmine/bin/mzmine
# some older versions or bad installations may be in:
# /opt/mzmine-linux-installer/bin/mzmine
```

```bash
# run headless with a CLI token
/opt/mzmine/bin/mzmine -cli-token "<TOKEN>" -batch /path/to/batch_file.mzbatch

# or login in the browser once, then run a batch
/opt/mzmine/bin/mzmine -login
/opt/mzmine/bin/mzmine -batch /path/to/batch_file.mzbatch
```
